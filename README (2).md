# Инвентарь лаборатории — прототип

Автономное веб-приложение для телефона: учёт реактивов, образцов и мест хранения,
сканирование Data Matrix камерой, печать этикеток на Niimbot D11_H по Bluetooth,
выгрузка в XLSX и CSV. Ни одного внешнего ресурса, работает без сети.

Светлая тема, чёрно-белая, один акцент — пыльный оранжевый. Им помечено только
то, что требует внимания: просрочка, «не найдено», активная кнопка, отметка в
сессии.

## Файлы

| файл | что это |
|---|---|
| `index.html` | приложение одним файлом, 251 КБ (включая niimbluelib) |
| `sw.js` | service worker — офлайн-кэш, версия `lab-inv-v11` |
| `manifest.webmanifest` | иконка и запуск в режиме приложения |

## Запуск

Web Bluetooth требует защищённого контекста: нужен `https://` или `localhost`,
`file://` не подойдёт. Положить три файла на хостинг, открыть на телефоне в
Chrome, «Добавить на главный экран». Перед первым подключением удалить принтер
из сопряжённых устройств системы, иначе ошибка GATT. Прошивку через родное
приложение Niimbot не обновлять.

При обновлении версии менять `CACHE` в `sw.js`, иначе телефон будет отдавать
старую сборку из кэша.

## Что на этикетке

Главное — название, набранное самым крупным кеглем. Номер ушёл в нижнюю строку
рядом с инициалами, он меньше названия и примерно вровень со строками данных.
Иерархия держится принудительно: если длинное название пришлось уменьшить,
номер уменьшается следом и никогда не становится крупнее.

```
┌──────────────────────────────────┐
│ ███  Q5 High-Fidelity            │  ← название, 2,5 мм
│ ███  500 мкл · L1234             │  ← данные, 1,5 мм
│ ███  до 2027-03-01 · −20° · A1   │
│      R0001                   ED  │  ← номер, 1,7 мм
└──────────────────────────────────┘
```

Название сначала пытается влезть в одну строку на самом крупном кегле, какой
позволяет ширина; если не вышло — переносится на две строки, и только если и
так не умещается ни при каком кегле — на три, отдав строки данных. Переносится
не только по пробелам, но и по дефисам: химические названия иначе не разбить.
На узких половинках, где слово не влезает целиком даже на минимальном кегле,
включается узкое начертание — это читается лучше, чем разрыв слова посередине,
и совпадает с тем, как половинки набраны в доке. Строки данных
заполняются по типу объекта (образец, реактив, вектор, мышь) и правятся вручную
перед печатью — раздел «Что на этикетке» в окне печати.

Для круглой этикетки на крышку всё осталось по доку: один круг с кодом, второй
с крупным номером. Названию там места нет, а номер в коробке читается без
сканера.

## Скорость сканирования

Было узко: модуль Data Matrix 0,42 мм — на грани для старой камеры. Сделано три
вещи.

**Символ увеличен** с 5 до 7 мм на 12×30 и до 6 мм на остальных.

**Код потерял дефис:** `S-0001` стал `S0001`. Буква и две пары цифр укладываются
в 3 кодовых слова вместо 4, то есть символ 10×10 вместо 12×12 — при той же
физической стороне модуль крупнее ещё на 15 %. Если дефис принципиален,
это одна строка в `newCode` в разделе DB.

Вместе: **0,42 → 0,68 мм**, рост на 62 %. По шаблонам — 0,68 на 12×30,
0,59 на половинках, флажке и кругах, 0,51 на третях.

**Сканер переписан.** Детектору отдаётся не весь кадр, а квадрат по рамке,
уменьшенный до 720 px: меньше пикселей на разбор, меньше фона, частота попыток
выросла (пауза 90 → 40 мс). Каждый пятый проход всё же смотрит полный кадр —
на случай, если код мимо рамки. Добавлены непрерывный автофокус, если камера
его умеет, и кнопка фонарика: на старых камерах подсветка даёт больше, чем всё
остальное вместе.

QR вместо Data Matrix не рассматривал: для такого короткого кода он требует
минимум 21×21 модуль против 10×10, то есть модуль вышел бы вдвое мельче.

## Места

Дерево раскрывается по уровням: у места с вложенными есть треугольник, справа
показано, сколько позиций лежит внутри с учётом всех вложенных мест. Клик по
названию открывает содержимое, карандаш — правку. Состояние раскрытых узлов
запоминается; на первом запуске раскрыт только верхний уровень. Сверху кнопка
«Раскрыть всё / Свернуть всё».

## Коды мест

Места тоже пронумерованы: `L0001`, `L0002` и так далее, отдельный префикс `L`,
чтобы не путались с содержимым. Код выдаётся при создании места, а местам,
заведённым раньше, дозаполняется при первом запуске новой версии.

Смысл не в нумерации, а в сканировании. Код на коробке убирает выбор из
выпадающего списка в трёх местах:

- **Начать инвентаризацию** — «Сканировать этикетку места» на вкладке
  «Инвент». Навёл камеру на полку — сессия открылась по ней. Если случайно
  отсканировал позицию, а не место, приложение возьмёт то место, где она лежит.
- **Переместить** — в окне перемещения кнопка скана: сканируешь коробку
  назначения вместо поиска её в списке.
- **Что здесь лежит** — скан кода места открывает его содержимое, оттуда же
  печатается этикетка и запускается инвентаризация.

На этикетке места крупно название, под ним путь («Лаборатория / −80 №1»),
затем тип и температура, внизу код. Если коробку вынули, по этикетке видно,
куда её вернуть.

Оговорка из твоего же дока: стойкость термопечати к −80 °C и азоту не
проверялась, тест (+4, −20, спирт, 37 °C) тоже ещё не проведён. Для коробок
в −80 это стоит проверить до того, как клеить их все.

## Два режима

Вкладка «Инвент» предлагает две разные задачи, у них разная механика.

### Перепись — завести то, чего в базе ещё нет

Место выбирается один раз (или сканируется) и держится в шапке. Тип тоже
липкий. Дальше цикл: назвал → «Создать и напечатать» → запись в базе, код
выдан, этикетка ушла в печать сама, форма очистила название и ждёт следующую.
Отдельного окна печати на каждую позицию нет — это лишние два касания на штуку.

Печать не задерживает ввод: задание уходит в фоновую очередь, форма
освобождается сразу. В шапке видно «печатается N». Очередь строго
последовательная — два задания принтер не переварит. Если печать сорвалась,
очередь останавливается, записи остаются и помечаются «без этикетки», а
кнопка «Допечатать» отправляет их заново.

Пауза между пакетами снижена с 10 до 5 мс — по твоему же доку качество
при этом не меняется, а на этикетку экономится около двух секунд.

У типа «набор/кит» есть поле **Этикеток**: в наборе несколько пробирок, и на
каждую нужна своя этикетка с тем же кодом. Печатается одним заданием в N
копий, а не N заданиями. Нашёл одинокий флакон — отсканировал — понял, от
какого он набора.

Две кнопки создания: **«Создать и напечатать»** и **«Создать без печати»**.
Вторая не трогает принтер вообще, даже не подключается к нему; запись
помечается «без этикетки», в шапке появляется счётчик, и позже «Допечатать»
отправит такие пачкой.

**«Ещё такой же»** продолжает в том же режиме, каким создали предыдущую
позицию: после «без печати» дубль тоже не печатается.

Кнопка **«+ коробка здесь»** создаёт место внутри текущего: родитель и
температура подставляются сами, тип по умолчанию «бокс». После сохранения
перепись переключается на новую коробку и её этикетка уходит в печать — то
есть завёл, наклеил, ссыпаешь пробирки и заносишь их уже туда.

**Ещё такой же** повторяет последнюю запись целиком, но с новым кодом: коробка
одинаковых аликвот — одно нажатие на штуку. Одинаковые позиции остаются
разными объектами, у каждой свой код и своя строка в базе.

**Отменить последнюю** удаляет запись вместе с её движениями — на случай, когда
ошибку видно сразу.

Если печать сорвалась (принтер уснул, крышка открыта), запись всё равно
сохраняется и помечается как «без этикетки». В шапке появляется счётчик и
кнопка «Допечатать N» — пачкой, когда принтер вернётся.

### Сверка — пройтись по тому, что уже в базе

Камера открывается один раз и не закрывается. Каждая отметка показывается
нижней панелью: название, код, что произошло, и счётчик «12 / 40». Повтор
того же кода в пределах двух секунд игнорируется, так что держать телефон над
этикеткой безопасно. Отсканированный код места в этом режиме не сбивает поток,
а неизвестный код закрывает камеру и открывает форму заведения.

### Как выйти из сверки

Неотмеченное не всегда значит «потеряно»: сверку могли прервать на середине
или сознательно посмотреть только часть полки. Поэтому на закрытии приложение
спрашивает, а не решает само:

- **Пометить «не найдено»** — статусы меняются, в журнал идут записи. Так
  правильно, если полку прошли целиком.
- **Оставить статусы как есть** — в отчёт эти строки попадают как
  «не проверено», ничего в базе не меняется. Для случая, когда прошли часть.
- **Не закрывать, отложить** — сессия остаётся открытой, отметки сохранены.
  На экране выбора режима висит напоминание с кнопкой «Продолжить»; сессия
  переживает закрытие приложения.

Если неотмеченных не осталось, вопрос не задаётся — сверка закрывается сразу.

## Поля по типу объекта

Форма показывает только то, что осмысленно для типа: у плазмиды нет срока
годности и производителя, зато есть позиция в боксе; у мыши — пол, возраст и
клетка вместо объёма; у оборудования — серийный номер. Обязательных полей
два: название и место.

## Найдено не на своём месте

Раньше это была дыра: сверка отмечала «найдено не по списку», но база
продолжала думать, что позиция в старом боксе. Теперь скан означает ровно то,
что значит физически — позиция переносится в место сессии, в журнал пишется
перемещение, статус «не найден» снимается. В панели сканера видно, откуда она
переехала.

## Инвентаризация

Позиция, заведённая прямо в сессии, сразу помечается как найденная и
записывается в базу — пересканировать только что наклеенную этикетку не нужно.
В списке она идёт как «заведено в сессии».

Сессия сохраняется после каждой отметки: телефон уснул или приложение
закрылось — при следующем запуске работа поднимется с того же места.

## Печать

Реализация твоя: niimbluelib, последовательность `connect → fetchRfidInfo →
newPrintTask → printInit → printPage → waitForPageFinished → waitForFinished →
printEnd`, плотность 3, пауза 10 мс, тип ленты из RFID-метки рулона с откатом
на `WithGaps`.

Вывод журнала пакетов убран целиком — вместе с подписками на `packetsent` и
`packetreceived`. Обработчик на каждый пакет и был тормозом, теперь его нет
даже выключенного.

Выбор шаблона переехал в «Экспорт → Принтер и этикетки»: там он задаётся один
раз, окно печати открывается сразу с ним. Поменять на лету всё ещё можно.

Геометрия по доку без изменений: 300 dpi, 1 мм = 11,81 px, головка 142 точки,
кегль по высоте заглавной буквы, порог черноты 140, поправка −0,5 мм для
круглых.

| шаблон | холст | модуль DM |
|---|---|---|
| 12×30 мм | 354×142 | 0,68 мм |
| 12×40 две половинки | 472×142 | 0,59 мм |
| 12×40 флажок | 472×142 | 0,59 мм |
| 12×40 три части | 472×142 | 0,51 мм |
| 28×14 два круга | 331×142 | 0,59 мм |
| линейка 30 мм | 354×142 | — |

На половинках и кругах выбирается второй объект: та же позиция, следующий номер
или любая другая из базы.

## Версия

Внизу вкладки «Экспорт» — версия приложения, дата сборки, версия схемы базы,
имя офлайн-кэша и состояние библиотеки печати. Версия и дата проставляются
при сборке, так что на телефоне всегда видно, что именно запущено. Кнопка
«Проверить обновление» дёргает service worker; если пришла новая версия,
она подхватится после перезапуска приложения.

При выпуске новой версии номер меняется одной командой сборки и автоматически
попадает и в страницу, и в имя кэша — рассинхрона между ними больше не будет.

## Где живут данные и как их не потерять

База лежит в IndexedDB браузера и привязана к **адресу** страницы. Из этого
следует главное:

- **Обновление приложения данные не трогает.** Залил новый `index.html` по
  тому же адресу — база на месте. Схема расширяется без потерь: новые таблицы
  и индексы добавляются, старые записи остаются.
- **Смена адреса обнуляет видимость базы.** Переезд с GitHub Pages на свой
  домен, смена поддомена или папки — для браузера это другой сайт, и старая
  база останется в прежнем. Поэтому адрес стоит выбрать один раз и не менять,
  а перед переездом снять копию.
- Очистка данных сайта в Chrome и удаление PWA с телефона стирают базу.

При запуске приложение просит у браузера постоянное хранилище
(`navigator.storage.persist`) — без этого Android вправе вычистить IndexedDB
под нехватку места. Текущий статус видно внизу вкладки «Экспорт».

### Резервная копия

«Экспорт → Сохранить копию (JSON)» снимает полный слепок всех семи таблиц.
Это то, что переносит работу на другой телефон, другой адрес или новую версию.

«Восстановить из копии» показывает, что внутри файла, и предлагает два
варианта: **добавить к текущему** (записи с теми же идентификаторами
перезаписываются, остальное остаётся — повторное слияние дублей не плодит) и
**заменить всё**.

После закрытия переписи приложение само предлагает сохранить копию.

XLSX и CSV — для чтения и отчётов, обратно они не заливаются. Для переноса
нужен именно JSON.

## Схема данных

Семь таблиц, имена и поля совпадают с тем, что уйдёт в SQLite нового LIMS:
`items` · `locations` · `stock` · `movements` · `audit_sessions` · `audit_results` · `meta`.
Хранилище — IndexedDB, журнал движений append-only.

Префиксы кодов: `S` образец и клетки, `R` реактив, `V` вектор AAV, `M` мышь —
из дока; сверх дока `P` плазмида, `C` расходник, `E` оборудование.

## Выгрузка

**XLSX** — лист на таблицу плюс плоская «Сводка» с полным путём локации,
признаком просрочки и датой последнего движения. Закреплённая шапка, автофильтр,
числа остаются числами.

**CSV** — ZIP из семи файлов, UTF-8 с BOM и разделителем `;`.
